翻譯系統與瀏覽數統計整合說明

用途
本檔案是網站維護與 AI 修改頁面時的唯一整合規格。新增或修改 PHP 頁面時，必須遵守下列流程，讓頁尾語言選單、繁中免翻譯與非繁中 Google Translate 都能正常運作。

一、翻譯系統：必要載入順序
1. 每個公開頁面設定 $pageKey 與 $pageScript，然後載入：require __DIR__ . '/_incview/header.php';
2. 頁面內容結尾必須載入：require __DIR__ . '/_incview/footer.php';
3. 不可自行複製頁首、頁尾、語言選單或 Google Translate 標記；共同元件集中在 _incview/header.php 與 _incview/footer.php。
4. header.php 會先載入 config.local.php，再載入 _inc/lang_loader.php。不要在個別頁面重複載入這兩個檔案。
5. 可用語言唯一來源為 config.local.php 的 $SUPPORTED_LANGS。新增、刪除或更名語言只能修改此陣列與 $LOCALE_MAP。

二、繁中與非繁中的運作規則
1. zh_TW 是預設繁體中文。網址沒有 lang 參數，或 lang=zh_TW 時，禁止輸出及載入 skin/js/translation.js，也禁止載入 Google Translate。
2. 使用者在頁尾 #languageSelect 選擇非 zh_TW 語言時，skin/js/site.js 必須寫入 googtrans=/zh-TW/{目標語言} cookie、記錄 wallpaperTranslateLang，並導向目前頁面的 ?lang={語言代碼} URL。
3. 非繁中頁面由 header.php 載入 skin/js/translation.js。該檔動態載入 Google Translate，將頁面原始繁中翻譯為選定語言。
4. 使用者選回 zh_TW 時，site.js 必須清除 googtrans cookie 與 wallpaperTranslateLang，再導向不帶 lang 的目前頁面 URL。
5. 語言控制項必須保留 notranslate 與 translate="no"，避免 Google 翻譯器翻譯自己的選單。
6. 若頁面使用嚴格 CSP，必須允許 translation.js 所需的 Google Translate 網域：translate.google.com、translate.googleapis.com、translate-pa.googleapis.com、www.gstatic.com、fonts.gstatic.com；否則選單只會改網址而不會翻譯內容。

三、外部檔案與 CSP 原則
1. 專案自有 CSS 全部放在 skin/css，專案自有 JavaScript 全部放在 skin/js；不可新增 inline CSS 或 inline JavaScript。
2. Google Translate 是非繁中才動態載入的第三方翻譯引擎。繁中頁面保持不載入它。
3. 不可把翻譯語言清單硬寫在 JavaScript；選單由 PHP 的 $SUPPORTED_LANGS 產生。

五、瀏覽數統計
1. footer.php 載入 skin/js/visitor-counter.js；該檔呼叫 ip_visitor_counter.php 更新頁尾的公開統計。
2. /visit_stats 是統計總覽，提供 UV、PV、趨勢、Host、頁面與最近訪問紀錄。
3. /visit_analytics 是深度分析，提供來源、Host、完整頁面的日期趨勢。
4. 統計相依檔案位於 _inc、_incview、skin/css、skin/js、skin/vendor。
